# 구현 계획

1. 리트레시 토큰은 레디스에 저장한다.
   - ** 레디스 다운시 데이터 소실됨 AOF 도입 **
2. 리프레시 토큰은 클라이언트도 가지고있는다.
    - 클라이언트가 제시할 "증명서로" 이를 기반으로 JWT를 재발급 한다.
3. JWT의 유효 기간은 1 ~ 5분으로 짧게 유지

---
#### AT가 만료된 경우
1. 서버는 특정 상태 코드 반환
2. 클라이언트는 특정 상태가 반환된 경우 RT와 함께 auth api 호출
3. 서버는 RT 검증 후 AT 재발급
   - RT는 일회용으로 사용
   - 사용후 AT와 같이 재발급
4. 클라이언트 재요청

#### RT가 만료된 경우
1. 만료 시간 지정해서 시간이 지난경우 자동 삭제

#### 로그아웃, 토큰 탈취 방지
1. 생성된 RT의 식별값은 서버에 저장
2. 요청받은 RT의 식별값 조회 후 없으면 예외
3. 있는데 만료되었으면 예외
4. 저장한 RT는 만료 기간이 지나면 삭제

#### RT 구조

````json
{
   "sub": "토큰 아이디",
   "type": "토큰 타입",
   "tid": "토큰 아이디",
   "iat": "토큰 생성일",
   "exp": "토큰 만료일"
}
````
